- Task 150: `client/e2e/release-gates.spec.ts` exercises direct public Event view, guest registration's return-to-sign-in flow, guest denial of notifications/admin routes, unlisted Event `noindex`, and robots exclusions. Playwright stubs only its Event/discussion API requests; it does **not** establish a real authenticated browse-to-approval/chat/organization/moderation journey. `corepack pnpm --filter @wasl/web exec playwright test e2e/release-gates.spec.ts`: 3 passed after fixing the test's initial query-string route mismatch; a subsequently added fourth keyboard case initially failed before the home heading loaded, then passed with `--grep "keyboard skip"` after waiting for page readiness. The production frontend build completed with the existing Stream SDK chunk-size warning.
- Task 151: `server/test/moderation.integration.ts` now checks that an Event moderator gains no authority over another Event even when accepted there, and suspension immediately removes in-app moderator authority. `corepack pnpm --filter @wasl/server exec tsx test/moderation.integration.ts` passed against the configured development database with rollback fixtures. This is not the full cross-module role and resource matrix, nor proof of immediate provider-side Stream removal.
- Task 152: `server/test/release-security.integration.ts` starts the built Nest API on a random localhost port and checks Helmet `nosniff`, allowed versus untrusted CORS origins, unauthenticated report denial and repeated-report throttling. `corepack pnpm --filter @wasl/server build` and `corepack pnpm --filter @wasl/server exec tsx test/release-security.integration.ts` passed. The first CORS assertion incorrectly expected an omitted response header; the server returns the configured trusted origin, which is still different from the untrusted request origin, and the corrected assertion passed. These checks do not constitute a complete OWASP/ASVS review.
- Task 152 dependency follow-up: `corepack pnpm audit --prod --audit-level high` initially reported 51 advisories (1 critical, 28 high, 20 moderate, 2 low). Updated pinned server Nest 11, Fastify 5, Drizzle ORM, shared/client/server Zod, React Router 7 and Unhead 2 within their current major versions. `pnpm-workspace.yaml` overrides vulnerable nested Fastify, js-yaml, lodash and path-to-regexp versions, and declares `@hookform/resolvers`' missing runtime Zod dependency. After reinstall, the production audit's JSON metadata reported **0 critical, 0 high, 0 moderate, 0 low**. An initial client build failed because the resolver could not import `zod/v4/core`; the package extension fixed the cause. Subsequent workspace typecheck/lint, server/client builds, focused notification/moderation/security integrations and all four browser release checks passed. Builds still warn about the existing large Stream chunk, and Rollup warns about two non-fatal comments in Zod. The pnpm update reported an unrelated webpack/schema-utils peer warning. A clean dependency scan is **not** proof that all ASVS controls are met.
- Lockfile review narrowed the `path-to-regexp` override to Nest dependencies so MSW keeps its own major version, and replaced the deprecated lodash `4.18.0` release with patched `4.18.1`. Reinstalled, then reran the production audit (0 vulnerabilities), workspace typecheck/lint, both builds, focused moderation/notification/API-security integrations, and all four browser release checks; all passed. The Zod/Rollup and Stream chunk warnings remain.
- Task 152 follow-up: the built API security check also rejects malformed public Event pagination (`pageSize=101`) and impossible date input (`from=2026-02-30`) with HTTP 400 before database access. The focused integration, lint and formatting checks passed. This does not cover authenticated DTO validation or all public filters.
- Task 153: A browser test checks keyboard skip-to-content focus and Arabic document language/direction. Contrast, screen-reader labels, mobile and reduced-motion behavior on all key screens remain open, as does approval of the WCAG baseline.
- Task 154: `client/public/robots.txt` no longer gives crawlers unrestricted guidance for known private/account/management routes; `client/src/app/RootLayout.tsx` also sets `noindex, nofollow` and avoids a canonical link on private routes. Browser checks cover guest sign-in redirects and private meta, without broadly blocking public Events. The app already sets client-rendered `noindex` for unlisted Events; robots guidance alone **does not guarantee** a URL is removed from search results, and a JS-rendered meta tag is not a server-side indexing guarantee. A production-origin sitemap, canonical audit, crawler tests and unlisted URL handling remain open.
- Task 157: [RELEASE_RECOVERY_RUNBOOK.md](RELEASE_RECOVERY_RUNBOOK.md) drafts an isolated backup/restore and migration recovery procedure without touching production. No restore was performed; RTO/RPO, isolated destination, object recovery and operator approval remain outstanding.
